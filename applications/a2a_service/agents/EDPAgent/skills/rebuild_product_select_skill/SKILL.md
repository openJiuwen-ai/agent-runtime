# 产品选择 Skill

## 职责

从上文产品列表中通过多轮对话（最多 5 轮）收集用户的选择和购买金额，
处理意图漂移，最终回复包含完整选品信息的结构化确认。

## 工具白名单（严格）

只允许调用以下工具：
- `ask_user`：向用户追问缺失信息（如未选产品、未填金额）

禁止调用 `recommend_product`、`buy_wealth` 或其他非白名单工具。

选品阶段不要直接发起业务工作流调用；只负责确认用户选择结果并组织结构化确认回复。


## 执行流程

### 第一步：获取产品列表

从当前对话上文中查找已展示的产品列表（productCode / productName / productType / profitValue / riskLevel）。

- **若上文中存在产品列表** → 直接使用，继续下一步。
- **若上文中没有产品列表** → 直接回复"暂无可选产品信息，请先获取理财推荐"，结束。

### 第二步：解析用户当前输入

尝试从用户输入中提取：

| 槽位 | 提取方式 |
|------|----------|
| 产品选择 | 序号（"第2个"）/ 产品代码（"XLT1801"）/ 产品名称关键词（"添利宝"） |
| 购买金额 | 数字 + 单位，"5万"→ 50000，"5000元"→ 5000，"50000"→ 50000 |

**金额解析规则：**
- "X万" → X × 10000
- "X千" → X × 1000
- 纯数字 → 直接使用
- 金额必须为正整数，最小 100 元

### 第三步：追问缺失信息（最多 3 次 ask_user 调用）

**若缺少产品选择：**
```
ask_user(question="请问您想选择哪款产品？请输入序号（如 1、2、3）或产品代码。")
```

**若缺少购买金额：**
```
ask_user(question="您打算购买多少金额？（请输入数字，单位元，如 50000）")
```

**若金额无效（如 0 或负数）：**
```
ask_user(question="金额需大于 0 元，请重新输入购买金额。")
```

### 第四步：意图漂移检测

遇到以下情况时，终止选品并给出对应回复：

| 用户意图 | 终止回复 |
|----------|----------|
| 想重新推荐（"换几个看看"、"重新推荐"） | "好的，已取消本次选品，请重新描述您的理财需求。" |
| 不想买了（"算了"、"不买了"、"取消"） | "已取消本次购买，感谢您的咨询，有需要随时告诉我。" |
| ask_user 调用已达 5 次仍无有效输入 | "选品已超时，如需继续请重新发起理财推荐。" |

### 第五步：确认并输出结构化选品结果

收集到完整的**产品选择**和**购买金额**后，先向用户展示并请求确认：

```
ask_user(question="请确认以下购买信息：\n- 产品名称：{productName}\n- 产品代码：{productCode}\n- 产品类型：{productType}\n- 预期年化收益：{profitValue}\n- 风险等级：{riskLevel}\n- 购买金额：{amount} 元\n- 理财卡尾号：{bankCardNumber}\n\n确认购买请回复"确认"，取消请回复"取消"。")
```

**用户回复"确认"/"是"/"好的"等肯定表达后**，输出最终结构化结果：

```
已确认您的选品信息：

- 产品名称：{productName}
- 产品代码：{productCode}
- 产品类型：{productType}
- 预期年化收益：{profitValue}
- 风险等级：{riskLevel}
- 购买金额：{amount} 元
- 理财卡尾号：{bankCardNumber}

选品已完成，正在为您进入资金筹划流程。
```

**用户回复"取消"/"不买了"等否定表达后**，终止选品：
```
已取消本次购买，感谢您的咨询，有需要随时告诉我。
```

**注意：结构化回复中的 productCode 格式必须完整保留**（如 `XLT1801`），供下游资金筹划流程使用。

## 规则约束

- 产品列表来自上文对话，不要自行调用任何查询工具。
- `ask_user` 累计调用不超过 5 次；超出后直接给出超时提示并结束。
- 同一轮追问中如果用户只回答了部分信息（如"第1个"但没有金额），不要强制合并，下一轮继续补问。
- 最终结构化回复必须包含 `productCode`，不可省略。
- 不要替用户做最终决策，必须由用户明确说出选择。
