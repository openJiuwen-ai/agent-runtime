# 集群创建与配置流程

## 入口与返回规则

集群管理负责选择目标集群。“新建集群”只登记服务实例，创建成功后使用 replace 跳转到该集群准入页，刷新不会再次创建。

每个已有集群固定拥有“配置工作台”，可从列表、各子页面返回。“继续配置”读取后端已保存的数据，依次检查：

1. 集群准入：至少一条有效、启用的用户或组织允许规则。
2. 运行资源：至少一条启用且未过期的运行规格绑定。
3. Agent 绑定：至少一条启用且未过期的 Agent 模板绑定。
4. 连接检查：查看组件状态，并使用已准入身份实际验证对话。

存在配置不等于实际可用。用户、组织、Agent 和运行资源的匹配范围仍需相互满足；组件在线也不代表对话已经通过验证。后端读取失败显示错误和重试，不把失败算成“未配置”。

## 唯一导航

| 导航 | 固定目标 | 内容 |
| --- | --- | --- |
| 配置工作台 | /instances/:id/cluster-config | 当前集群进度、下一步、绑定摘要 |
| 集群准入 | /instances/:id/access | 用户和组织准入 |
| 运行资源 | /instances/:id/service-resources | 运行规格绑定、调度范围与优先级 |
| Agent绑定 | /instances/:id/agent-resources | Agent 使用范围，关联专家包管理入口 |
| 其他配置 | /instances/:id/other-settings | 日志配置、配额管理、成本统计（待开放）、业务审计（待开放） |
| 连接状态 | /instances/:id/status | 地址维护、探活、当前集群用户面入口 |

所有页面使用同一套六标签导航，不再设置“集群配置”“配额管理”中间层。专家包保留在 Agent绑定下，进入专家包时仍高亮 Agent绑定。旧实例根地址归一到工作台，旧 resources 路径归一到 Agent绑定；旧向导书签进入真实集群页面。

配置步骤、进度和“继续配置”只在配置工作台展示。集群准入、运行资源、Agent绑定、其他配置、连接状态等子页面仅保留模块导航和返回工作台，不显示步骤条或上一步/下一步/继续配置操作。顶部配置引导的当前集群入口也统一打开配置工作台。弹框关闭保留未保存确认；保存结果由后端和工作台进度反映。

## 其他配置：目录定位与单页编辑

左侧目录按“日志配置 / 配额管理 / 成本统计 / 业务审计”分组；右侧连续内容区在一屏内滚动。每个设置都有独立标题、说明与操作。目录点击直接定位对应设置，滚动同步当前位置；切换目录不卸载已经打开的表单，不会丢掉本页未保存的填写。各项独立保存，避免将不同后端能力包装成一次原子提交。刷新恢复定位，已保存配置始终从后端读取。

| 分组 | 设置 | 查询参数 setting | 能力 |
| --- | --- | --- | --- |
| 日志配置 | 日志脱敏 | log-masking | 现有规则 CRUD |
| 日志配置 | 日志级别 | logging | 默认、控制台及各组件级别 |
| 日志配置 | 高级审计日志 | audit-log | 审计字段、采集与输出配置，不等于业务审计查询 |
| 配额管理 | 定时任务配额 | cron-quota | 每用户 Web 面板启用且未过期任务上限，0 不允许继续启用新任务 |
| 配额管理 | 用户空间配额 | workspace-quota | 按范围配置容量及查看用量，遵循 workspace 功能开关 |
| 配额管理 | 团队配额 | team-quota | 团队数量、成员规模及用量 |
| 配额管理 | Token配额 | token-quota | 待开放，没有可读写接口 |
| 成本统计 | 成本统计 | cost | 待开放 |
| 业务审计 | 业务审计 | business-audit | 待开放 |

日志类与定时任务策略沿用管理员权限；配额沿用 quota:read / quota:write。没有权限或未开启功能时不挂载真实 API 编辑器。演示集群采用同一布局，显示只读示例，不提交真实配置。日志级别、定时任务与高级审计初次读取 404 时，现有表单显示未托管及默认值，不把它视为已保存。

旧书签用 replace 归一化，保留集群与模板返回上下文：

- config?configTab=logMasking / logging / auditLog / cronPolicy → other-settings?setting=对应设置。
- workspace-quota / team-quota / token-quota / cost / audit → other-settings?setting=对应设置。
- quota → 根据 workspace 功能开关定位用户空间配额或团队配额。

## 跨页面准备资源

- 从准入进入用户/组织目录，保留目标集群，目录与组织编辑页可返回原集群对应准入页。
- 从运行资源绑定进入运行规格与容器模板目录，保留目标集群与绑定草稿。选择模板返回后只预填，仍由用户确认保存。
- 运行规格编辑中新增容器模板使用子弹框，原运行规格表单不会因跳页丢失。
- 从 Agent 绑定进入模板目录、详情或新建模板，保留目标集群与绑定草稿。返回时消费一次性创建/选择参数，防止刷新重复打开错误流程。
- 普通页签跳转不携带上一个列表的筛选或弹框参数；仅保留集群创建流程必要上下文。

## 数据与提示

创建前草稿按账号和准备上下文隔离，在当前浏览器标签页的 sessionStorage 中恢复。创建成功后清除草稿。创建失败保留填写内容。已有配置始终从后端读取，不以浏览器中的向导步数作为完成依据。

每个页面最多保留一个底部 WorkspaceNote，说明本页职责。去掉重复顶部说明条、子面板说明和全局离线提醒。后端离线开关保持原样；移除提醒不改变服务行为。

“检查连接”调用现有 health-probe API，该 API 检查全部集群的组件地址，因此按钮明确标明作用范围。“进入当前集群用户面”先确认当前身份的 Agent 上下文，再设置该集群的活动 Cookie 并进入 /chat/，避免默认进入其他集群。
