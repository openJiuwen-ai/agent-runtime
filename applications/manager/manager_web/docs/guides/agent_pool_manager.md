# 运行时模板

运行时模板定义 AgentServer 实例池的运行方案：用哪些容器、挂载哪些卷，以及实例池的容量与超时参数。模板本身不直接生效，绑定到集群后，集群才按它拉起并管理 AgentServer Pod：有会话时按需扩容，空闲后自动回收。

## 使用流程

1. 已登录管理员打开 **工作台 → 运行时资源 → 容器模板**，准备好 AgentServer 主容器模板；需要沙箱时再准备一个 Sandbox 模板
2. 打开 **工作台 → 运行时资源 → 运行时模板**，点击 **新建运行时模板**，绑定容器并按需调整参数
3. 进入目标集群的 **运行资源**，添加该模板并设置使用范围
4. 授权用户发起会话后，集群按模板拉起和管理 AgentServer Pod

## 新建运行时模板

进入 **工作台 → 运行时资源 → 运行时模板**，点击 **新建运行时模板**。带 `*` 的字段必填。点击 **保存** 时如有必填项未填或数值越界，会展开所在分组、定位到该字段并给出提示，修正后才能保存。

也可以点击 **读取默认模板**，从部署时交付的默认配置开始，在其基础上修改。

### 基本信息

| 字段 | 说明 |
| ---- | ---- |
| **模板名称** | 必填。最多 128 个字符 |
| **模板描述** | 可选。最多 512 个字符 |

### 容器配置

| 字段 | 说明 |
| ---- | ---- |
| **主容器模板** | 必填。从容器模板目录中选择 AgentServer 主容器。未绑定主容器的模板无法拉起 AgentServer。列表里没有合适的模板时，点击 **新建容器模板** 现场创建 |
| **SideCar 容器模板** | 可选。可添加多个，通常是与主容器同 Pod 部署的 Sandbox。SideCar 与主容器的容器 ID 不能相同，SideCar 之间也不能重复 |

容器的镜像、端口、资源等规格不在这里设置，统一在 **容器模板** 中维护。

### 容量与超时

这一组全部必填，已预填默认值，保持默认也可以保存。取值均为整数，上限 2147483647。

| 字段 | 取值范围 | 说明 |
| ---- | ---- | ---- |
| **最小空闲 Pod 数** | 0–2147483647，默认 0 | 常备热备 Pod 数，配置下发后即预热，0 表示按需拉起。实际数量不超过实例池的最多 Pod 数 |
| **单 Pod 并发上限** | 1–2147483647，默认 2 | 单个 Pod 同时处理的会话数，过大易互相争抢资源 |
| **Scope 并发数** | 1–2147483647，默认 3 | 实例池同时服务的会话总数上限。最多 Pod 数 = ⌈Scope 并发数 ÷ 单 Pod 并发上限⌉ |
| **空闲 Pod 回收 TTL（秒）** | 1–2147483647，默认 300 | 热备数之外，空闲超过该时长的 Pod 会被回收 |
| **会话TTL（秒）** | 1–2147483647，默认 60 | 会话空闲超过该时长后，释放其占用的并发额度 |
| **单次消息超时（秒）** | 1–2147483647，默认 600 | 单次消息处理的最长等待时间 |
| **Gateway就绪探针超时时间（秒）** | 1–2147483647，默认 300 | 新建 Pod 后等待其就绪的最长时间，超时则本次拉起失败 |
| **Gateway就绪探针探测间隔（秒）** | 1–2147483647，默认 2 | 等待新 Pod 就绪时的轮询间隔，越小发现越及时 |

### 部署与存储

这一组全部可选，一般保持默认。

| 字段 | 格式 / 取值范围 | 说明 |
| ---- | ---- | ---- |
| **节点名称** | 字母、数字、`-`、`.`，以字母或数字开头和结尾，最多 128 个字符 | 将 Pod 固定调度到指定节点，留空由调度器分配 |
| **fsGroup** | 0–2147483647 的整数 | Pod 卷的属主组 ID，用于控制挂载卷的文件权限，留空则不设置 |
| **Pod名称** | 最多 128 个字符 | Pod 名称前缀，留空使用默认值 `agentserver` |
| **SSE 路径** | 以 `/` 开头的绝对路径，最多 128 个字符 | AgentServer 事件流接口路径，留空使用默认值 `/api/v1/events/stream` |
| **K8S凭据文件路径** | 最多 512 个字符 | 运行面管理 Pod 所用的 kubeconfig 路径，按部署约定填写，通常留空 |
| **Volumes** | JSON 对象数组 | Pod 级卷定义，卷源可选 `hostPath`、`configMap`、`secret`、`persistentVolumeClaim`、`nfs`、`emptyDir` |

Volumes 示例：

```json
[{"name":"data","persistentVolumeClaim":{"claimName":"jiuwenswarm-pvc"}}]
```

在 **容器模板** 的 volumeMounts 中按名称引用这里定义的卷。保存时会校验两者的对应关系：没有被任何容器挂载的卷，以及引用了未定义卷的挂载，都无法保存。

## 编辑、禁用与删除

- **编辑**：点击行内 **编辑**。已被集群使用时，保存后变更会下发，相关 AgentServer Pod 按新配置重建，已有会话不受影响，建议在业务低峰期修改
- **禁用**：通过 **已启用** 列的开关控制。禁用后不能再被集群新添加；仍被 Agent模板 引用时不能禁用
- **删除**：点击行内 **删除**。仍被集群或 Agent模板 引用时删除会被拒绝，需要先解除引用

## 导入与导出

- **导出**：点击行内 **导出**，下载该模板的实例池定义 JSON
- **导入**：点击列表页 **导入**，选择此前导出的文件重建模板。文件中含容器模板时会一并创建，含多个运行时模板时只导入第一个
- **导入默认配置**：点击列表页 **导入默认配置**，一键导入部署阶段交付的默认 `agentserver.json`（含容器模板）。提示暂无默认配置时，请确认产品面 runtime 已部署

## 注意事项

- 调大 **Scope 并发数** 或 **单 Pod 并发上限** 即提高容量上限，同时应保证容器模板的 CPU / 内存上限设置合理，并确认集群资源充足
- **最小空闲 Pod 数** 大于最多 Pod 数时，热备数量按最多 Pod 数为准
