The first release of Agent Runtime focuses on **low-code** Agent publishing: it works with openJiuwen Studio. After you provide the Agent IR file, you can deploy in one step and bring the Agent service online.

We recommend using Runtime from **source**: clone the repository and use the startup script for a one-step install and launch.

## Prerequisites

- Python >= 3.11.4
- `uv` >= 0.25.x
- `git` (clone the repository)
- `bash` (Linux / macOS) or **Git Bash** (Windows)

## Start Runtime in one step

### 1) Prepare environment configuration

Refer to [Configuration](<2. Configuration.md>) to create and edit the `.env` file, and adjust runtime parameters as needed. Key configuration items are as follows:

- `DB_TYPE`: `mysql`, `sqlite`, `gaussdb`, or `opengauss`
- Other runtime settings (e.g. IP address, port)

Additional notes:

- The default install only includes dependencies for `sqlite` and `mysql`.
- When `DB_TYPE=gaussdb` or `DB_TYPE=opengauss`, Runtime also needs `async-gaussdb`.
- For a manual setup, run `uv pip install -e "./foundation[gaussdb]"`.

### 3) Run the startup script

From the **repository root** (`agent-runtime/`):

**Linux / macOS:**

```shell
set -a; source .env; set +a
```

### 2) Install the Runtime package

**Linux/MacOS/Windows (Git Bash):**

```shell
# Create and activate an isolated virtual environment:
uv venv
source .venv/Scripts/activate   # Windows(Git Bash)
source .venv/bin/activate       # Linux/MacOS
# Install the runtime server package:
uv pip install agent-runtime-server
```

### 3) Start the Runtime service

**Linux/MacOS/Windows (Git Bash):**

```shell
python -m openjiuwen_runtime.server.main
```

By default, Runtime is available on port **8186**.

## Publishing agents

Runtime supports two publishing paths: **low-code** (one-click from Studio) and **high-code** (not yet available).

## Publish a low-code agent via Studio

After Runtime is running, configure Runtime’s host and port in openJiuwen Studio’s backend `.env`. Once connected, you can publish Agents from Studio in one click.

### Configure Runtime in Studio

At the **agent-studio** repository root, copy `.env.example` to `.env` and set Runtime connectivity:

```shell
# Runtime connectivity (example)
RUNTIME_HOST=localhost
RUNTIME_PORT=8186
```

### Publish an agent

#### Steps

1. Open the agent editor, finish configuration and debugging, then click **Publish**.
2. A publish dialog opens. Choose a draft or a previously submitted version. If you pick a draft, submit it as a new version first, then publish.

![Publish](images/runtime-publish.png)

3. After a successful publish, a success card appears. Click **Publish management** to open the publish management page and inspect details.

![Publish success](images/runtime-publish-success.png)

4. After publishing, **Publish management** appears in the top-right of the agent editor. Hovering **Publish** also shows publish status.

![Publish info](images/runtime-publish-info.png)

### Try a conversation

On the publish management page, use the **Conversation** tab to chat with the deployed agent.

![Chat](images/runtime-management-chat.png)

### API examples

The **API** tab shows how to call the running agent (method, URL, body, response shape, etc.). Values you enter in the request form are reflected in the curl / Python / JavaScript samples on the right for easy copy-paste.

![API samples](images/runtime-management-api.png)

### Unpublish an agent

When you no longer need the running instance, open publish management and click **Unpublish** on the right. Confirm in the dialog; the system removes the runtime deployment. On success, you are returned to the agent list.

![Unpublish](images/runtime-management-offline.png)
