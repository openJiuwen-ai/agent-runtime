This document describes the core configuration file **`server/.env`** used when deploying Runtime: what it does, which environment variables it contains, how each setting behaves, and practical change guidance so operators and developers can configure Runtime correctly (including low-code Agent and runtime-server).

All variables in this file are part of how Runtime starts and runs. Follow configuration conventions when editing; invalid values can prevent startup or cause runtime errors. The sections below group settings by category.

# Database

## Common database settings

### DB_TYPE (database engine)

**Purpose:** Selects the database backend for Runtime. Only **`mysql`** and **`sqlite`** are supported. Do not use other values. Default is **`sqlite`**.

**Guidance:** Set to `sqlite` or `mysql` to match your deployment. For MySQL, ensure the database server is running and that the MySQL-specific variables below match your environment.

## MySQL-only settings

### DB_HOST (MySQL host)

**Purpose:** Hostname or IP of the MySQL server Runtime connects to.

**Guidance:** Use the remote host’s public IP if MySQL is remote; use `127.0.0.1` or `localhost` if MySQL is on the same machine as Runtime. Ensure the host is reachable from the Runtime host (firewall / security groups / ports).

### DB_PORT (MySQL port)

**Purpose:** MySQL listen port.

**Guidance:** Set to your MySQL server’s actual port. If you use **SQLite**, this value is ignored but you may comment it out to avoid confusion.

### DB_USER (MySQL username)

**Purpose:** MySQL user Runtime uses. The account needs sufficient privileges (read/write, DDL such as table creation) for Runtime to operate the schema.

**Guidance:** Avoid `root` in production. Prefer a dedicated account (e.g. `jiuwen_runtime_user`) with least privilege on the database named in `DB_NAME` only.

### DB_PASSWORD (MySQL password)

**Purpose:** Password for `DB_USER`.

**Guidance:** Always use a strong password in production (mixed case, digits, symbols, length ≥ 8). Avoid trivial passwords. Store and rotate secrets securely.

### DB_NAME (MySQL database name)

**Purpose:** Database name Runtime uses. On startup, Runtime validates that the database exists; it **does not** auto-create the database — create it yourself in advance.

**Guidance:** You may use different names per environment (e.g. `prod_jiuwen_runtime`, `test_jiuwen_runtime`). Ensure the database exists and that `DB_USER` has the required privileges.

# Deployment-related settings

These control where Runtime and low-code Agents run, image references, and on-disk layout for deployments.

## IP (host IP for services)

**Purpose:** Network address shared by **agent-runtime-server** and the low-code Agent components on the host.

**Guidance:** **Required** — no default. Set to the real public (or reachable) IP of the machine where runtime-server and the low-code Agent run.

## LOWCODE_IMAGE (low-code Agent container image)

**Purpose:** Container image for the low-code Agent. When `DEPLOY_TYPE` is **`docker`** or **`k8s`**, Runtime pulls this image to start the low-code Agent container.

**Guidance:** **Required** — no default.

## DEPLOY_DIR (deployment working directory)

**Purpose:** Directory for deployment artifacts (configs, temp files, etc.). Supports absolute paths (e.g. `/data/deploys`) or paths relative to the **project root** (e.g. `deploys`). Relative paths are resolved against the project root. The directory is created if missing.

**Guidance:** Default is `/tmp/deploys`. Prefer a disk with enough space and good I/O. Ensure the Runtime process user can read/write the directory.

## DIST_DIR (wheel / distribution directory)

**Purpose:** Directory holding `.whl` packages needed to run the low-code Agent. Runtime loads wheels from here at startup. Supports absolute paths or paths relative to the project root. Created if missing.

**Guidance:** Default is `/tmp/dist`. Ensure the process user can read this directory.

# Runtime / process settings

These control how runtime-server listens and how `uv` behaves.

## HOST (bind address)

**Purpose:** Address **agent-runtime-server** listens on.

**Guidance:** Default **`0.0.0.0`** accepts connections on all interfaces (typical for production). For internal-only access, you may bind to a private IP. Avoid binding only to `127.0.0.1` if external clients must connect.

## PORT (listen port)

**Purpose:** TCP port for **agent-runtime-server**.

**Guidance:** Default **`8186`**. If the port is in use, pick another free port (prefer ≥ 1024). Update clients and firewall rules accordingly; in production, restrict who can reach the port.

## UV_EXTRA_ARGS (extra arguments for `uv`)

**Purpose:** Appends global extra flags to `uv` invocations. Useful when `uv pip install` fails due to TLS, custom CAs, or mirror connectivity in restricted networks.

**Guidance:** Example values such as `"--native-tls --allow-insecure-host mirrors.aliyun.com -i https://mirrors.aliyun.com/pypi/simple/"` are **examples only** — adjust for your environment.

Typical cases:

- If public PyPI works, you may not need mirror flags;
- For private mirrors, set `-i https://your-registry/pypi/simple/`;
- For certificate issues, consider `--allow-insecure-host` for specific hosts; **`--no-ssl-verify` is discouraged in production**;
- Separate arguments with spaces and wrap the whole string in double quotes.

# Startup / deployment strategy

These control how **runtime-server** starts low-code Agents: **`subprocess`**, **`docker`**, or **`k8s`**.

## DEPLOY_TYPE (deployment strategy)

**Purpose:** Selects how low-code Agents are started:

- **`subprocess`** (default): runtime-server runs as a process; low-code Agent type follows each deploy request;
- **`docker`**: use containerized low-code Agents regardless of request details — for containerized deployments;
- **`k8s`**: use Kubernetes-orchestrated low-code Agents — for K8s deployments.

**Guidance:** Match the value to your actual environment:

- Process-based runtime-server → `DEPLOY_TYPE=subprocess`
- Docker-based runtime-server → `DEPLOY_TYPE=docker`, correct `LOWCODE_IMAGE`, Docker daemon available
- K8s-based runtime-server → `DEPLOY_TYPE=k8s`, cluster and `LOWCODE_IMAGE` configured, Runtime has permission to orchestrate workloads

# General editing notes

- Use `KEY=value` with **no spaces** around `=`, or parsing may fail;
- Lines starting with `#` are comments;
- After changing `.env`, **restart runtime-server** for changes to take effect.
