# JiuwenSwarm 企业版产品简介

JiuwenSwarm 是 openJiuwen 社区的多智能体协作系统，通过任务拆解、专业分工和动态协作，帮助用户完成复杂任务。**JiuwenSwarm 企业版面向多部门、多用户共同使用 Agent 的场景，在个人版协作能力的基础上，提供资源弹性、多租隔离、统一管控和安全审计能力。** 企业可以将其部署在自己的服务器集群中，以统一的服务向员工提供 Agent 能力，并集中管理运行资源与访问权限。

企业版由 JiuwenSwarm 承载多智能体任务执行，Agent-Runtime 管理会话与运行资源，Manager 统一维护身份、能力和集群配置。员工通过浏览器等入口使用已获授权的 Agent，管理员则在管理面配置谁能使用、可以使用哪些能力，以及任务使用什么运行资源。

## 核心能力

### 资源弹性

企业中的请求量和任务时长会随业务变化。Agent-Runtime 按配置管理 AgentServer 资源池，优先复用已有会话绑定和可用容量，在容量不足时增加运行实例，实例空闲并满足回收条件后释放多余资源。管理员可以设置基础保留容量、规模上限、并发阈值和空闲回收时间，在响应体验与资源成本之间进行调整。

企业版也支持关键服务的多副本部署，通过共享状态和后台任务协调，为横向扩展和故障恢复提供基础。

### 多租隔离

企业版从资源、数据和权限三个方面划分使用边界。管理员可以按用户或部门配置专用资源或共享资源池；不同租户的执行上下文、会话历史和工作文件分别管理；用户能够使用的 Agent、模型、技能和工具由授权与策略共同约束。企业在统一建设服务的同时，可以为不同业务提供各自适用的能力与资源。

### 统一管控

Manager 提供集中的管理入口，覆盖用户、组织、角色、集群准入、Agent 模板、运行资源和配额等配置。管理员可以将模型、Skill 和工具组合为可复用的 Agent 模板，再绑定到目标集群并分配给相应用户或组织，减少逐个实例维护配置的工作。

企业已有的身份认证、业务接口和技能目录也可以通过受支持的协议与扩展机制接入，让现有系统与 Agent 服务共同使用。例如，通过 OIDC 对接企业身份源，实现单点登录，再在平台内分配资源权限。

### 安全与审计

企业版围绕身份、服务链路和执行环境提供分层防护。用户访问前校验身份与 Agent 使用权限，内部服务可按需启用双向 TLS（mTLS）认证；工具安全护栏约束允许执行、需要确认或应当拒绝的操作，JiuwenBox 沙箱为工具和代码执行提供受控环境。

平台支持基于 OpenTelemetry 的运行观测和结构化审计事件采集，记录用户接入、会话、文件、沙箱及技能授权等关键行为。结合企业部署的采集、存储和查询平台，可以定位执行问题并追溯关键操作。具体字段、采集范围和导出链路可按业务需要配置，详见[审计日志](核心功能/统一管理平台/集群管理/集群配置/审计日志.md)与[全链路安全](核心功能/全链路安全.md)。

## 与个人版的区别

个人版侧重个人工作环境中的使用与探索，企业版侧重多人共享服务时的运行承载和集中治理。可以按使用方式选择：

| 比较维度 | 个人版 | 企业版 |
| --- | --- | --- |
| 主要场景 | 个人办公、开发验证和新能力体验 | 多部门、多用户共享 Agent 服务，统一建设与运营 |
| 部署方式 | 在本地电脑安装并启动，可使用桌面端或命令行方式 | 在 Linux 服务器上以容器镜像部署，当前需要 Kubernetes 或 OpenShift 集群 |
| 运行资源 | 主要使用本机资源，由本地环境承载任务 | 由分布式运行时管理资源池，按策略分配、扩容和回收实例 |
| 配置管理 | 围绕本地使用配置模型、技能和工具 | 在管理面集中管理身份、权限、能力模板、集群与配额 |
| 安全与隔离 | 面向个人环境的工具权限和访问控制 | 面向多用户服务的租户隔离、集中授权、沙箱及可配置的安全审计 |
| 功能取向 | 适合探索新能力与实验性功能 | 根据企业版设计主张、安全要求和运维方式提供相应功能 |

**个人版与企业版共用代码主干，均在 [JiuwenSwarm 仓库的 develop 分支](https://gitcode.com/openJiuwen/jiuwenswarm/tree/develop)持续演进。** 两者共享核心技术与协作能力，但具体开放的功能并不完全相同。企业版会根据产品设计和安全考虑，对少量功能进行适配、限制或暂不开放。如果希望体验实验性功能，建议先在个人版中尝试；企业版的可用功能以对应发布版本及配套文档为准。

## 部署与开始使用

**个人版在本地启动。** 安装桌面端，或通过命令行安装并启动服务后，即可在本机配置模型并开始使用，无需为个人使用先搭建 Kubernetes 集群。安装方式与使用步骤见 [JiuwenSwarm 个人版安装说明](https://gitcode.com/openJiuwen/jiuwenswarm/blob/develop/README.md)和[个人版快速上手](https://gitcode.com/openJiuwen/jiuwenswarm/blob/develop/docs/zh/Quickstart.md)。

**企业版当前采用服务器镜像部署。** 部署前需要准备好 Linux 服务器和 Kubernetes 环境，也支持基于 Kubernetes 的 OpenShift 部署形态。使用配套部署工具与组件镜像，完成存储、数据库等基础服务准备，再启动运行面和管理面。员工在自己的电脑上通过浏览器访问服务器提供的服务，无需各自安装一套运行环境。

首次使用可按[快速上手](快速开始/快速上手.md)完成环境准备、服务启动、用户授权和首次对话；具体部署参数、存储接入、组件启动与升级方式见[集群部署指南](快速开始/集群部署指南.md)。需要了解各组件职责及协作关系时，可继续阅读[整体架构](整体架构.md)。

后续企业版也在考虑提供更轻量的本地部署方式，便于开发验证和小规模使用。该形态尚未发布，具体能力与时间以社区后续公告为准，敬请期待。
