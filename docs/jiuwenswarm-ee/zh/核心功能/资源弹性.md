# 资源弹性


## 功能说明

AgentServer 以**动态实例池**方式运行：会话到来时按需拉起 Pod，空闲后自动回收，支持常备热备 Pod。整个过程由运行面自动完成，管理员只需在[运行时模板](./统一管理平台/运行时模板.md)中设置实例池参数，无需手工扩缩容。

一个集群里每个[运行时](./统一管理平台/集群管理/集群配置/运行时.md)对应一个独立的实例池，互不占用资源。用户发起会话时，系统按优先级命中一个运行时，在它的实例池里分配 Pod：优先复用有空位的在用 Pod，没有空位就新建，达到上限则不再新建。会话结束后额度释放，Pod 空闲超过回收时长即被删除。

## 弹性机制

| 机制 | 行为 |
| ---- | ---- |
| **按需扩容** | 现有 Pod 全部满载时，新会话自动触发新建 Pod，直到容量上限 |
| **容量上限** | 最多 Pod 数 = ⌈Scope 并发数 ÷ 单 Pod 并发上限⌉。达到上限后不再新建，需调大并发参数扩容 |
| **热备** | 「最小空闲 Pod 数」内的空闲 Pod 常驻不回收；配置下发后即预热，无需等首个请求，新会话零等待 |
| **空闲回收** | 热备底数之外、空闲超过「空闲 Pod 回收 TTL」的 Pod 自动删除，低峰不空跑 |
| **会话亲和** | 一个会话始终固定在同一个 Pod 上处理，消息不跨 Pod；会话空闲超过「会话 TTL」才释放占用 |
| **配置热更新** | 修改实例池参数后立即按新参数管理：热备数、回收阈值实时生效；已有会话不中断 |

## 参数速查

参数在「工作台 → 运行时资源 → 运行时模板」新建或编辑弹窗的「容量与超时」分组中设置，均为必填并已预填默认值：

| 参数 | 取值范围 | 默认值 | 说明 |
| ---- | ---- | ---- | ---- |
| **最小空闲 Pod 数** | 0–2147483647 的整数 | 0 | 常备热备 Pod 数。0 表示完全按需，无请求时不占资源；实际数量不超过最多 Pod 数 |
| **单 Pod 并发上限** | 1–2147483647 的整数 | 2 | 单个 Pod 同时处理的会话数。过大易互相争抢资源，过小则 Pod 数偏多 |
| **Scope 并发数** | 1–2147483647 的整数 | 3 | 该实例池同时服务的会话总数上限，决定容量天花板 |
| **空闲 Pod 回收 TTL（秒）** | 1–2147483647 的整数 | 300 | 热备之外空闲 Pod 的回收等待时长 |
| **会话TTL（秒）** | 1–2147483647 的整数 | 60 | 会话空闲多久后释放并发占用 |
| **单次消息超时（秒）** | 1–2147483647 的整数 | 600 | 单次消息处理的最长等待，超时按失败处理 |
| **Gateway就绪探针超时时间（秒）** | 1–2147483647 的整数 | 300 | 新建 Pod 后等待就绪的最长时间 |
| **Gateway就绪探针探测间隔（秒）** | 1–2147483647 的整数 | 2 | 等待新 Pod 就绪时的轮询间隔 |

## 典型场景

| 场景 | 建议 |
| ---- | ---- |
| 试用、小规模使用 | 保持默认即可：无请求时不占资源，首条消息稍慢（需现场拉起 Pod） |
| 高峰响应要快 | 最小空闲 Pod 数设为 1–2，常见高峰时段常备热备 |
| 低成本优先 | 热备保持 0，适当调小空闲回收 TTL，用首条消息的等待换资源占用 |
| 并发量大 | 按并发评估调大 Scope 并发数，必要时同时调大单 Pod 并发上限，并确认集群资源与容器 CPU / 内存上限匹配 |

## 注意事项

- 容量上限由两个并发参数共同决定，且受集群实际资源约束：调参前先确认节点余量与容器模板中的资源上限。
- 回收只针对空闲 Pod，正在处理会话的 Pod 不会被回收。
- 修改运行时模板会触发相关实例池的 Pod 重建（已有会话不受影响），短时间内连续修改可能被容量保护暂时拒绝，建议在业务低峰期变更。
